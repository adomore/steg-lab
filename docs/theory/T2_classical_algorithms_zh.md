# T2 -- 经典嵌入算法

> Gate：**G2** -- `python3 gates/g2_classical.py` -- 已通过

## 2.1 为什么要自己实现

你无法为一个自己没实现过的算法建检测器，因为你不会知道它哪些性质是本质的、哪些是
偶然的。最清楚的例子就是本章开头这一对。

## 2.2 LSB replacement 与 LSB matching

**replacement** 覆写最后一位。**matching** 在该位本就不符时随机加一或减一。它们听
起来像同一个想法的两个变体，其实不是。

replacement 只能在一对值的两个成员之间移动：2i 到 2i+1，或者反过来。于是
`floor(x/2)` 是不变量，直方图里成对的计数被推向它们的共同均值。这个不变性是一种
**结构**，而 RS 分析、Sample Pair Analysis 与 Weighted Stego 全都是「这个结构被侵蚀
了多少」的估计量。

matching 会跨越对边界。那个结构根本不会形成。

嵌入器只改了一行。Gate G4 量出了它让检测器付出的代价：在每像素 0.25 比特下，
Weighted Stego 对 replacement 的 AUC 是 1.000，对 matching 是 0.550。T4 展开这一点。

两者平均都是每嵌入两比特改动一次，所以嵌入效率都是 2.0——每次改动携带一比特，这就
是矩阵编码要去超越的朴素基准线。

## 2.3 Jsteg 与第一次真正的攻击

Jsteg 对量化后的 DCT 系数做 LSB replacement，跳过值 0 与 1。这个跳过就其自身而言是
说得通的：改动它们会很显眼。但这意味着 Jsteg 碰过的直方图对被抹平了，而它跳过的那
一对没有。

Gate G2 判据 D 在真实系数上量了这个反差。值 2 与 3 的计数失衡从 0.334 降到 0.034，
而值 0 与 1 的计数比漂移不到 5%。

这个反差就是卡方攻击的全部依据——针对真实隐写工具的第一次公开破解，而且不到一年就
来了。一个出于正当理由做出的设计决定，制造了签名。

## 2.4 F5 与矩阵编码

矩阵编码是让 F5 变得重要的那个想法。不再每个系数写一比特，而是用 (1, 2^k - 1, k)
汉明码：把 k 比特写进 2^k - 1 个系数，**最多只改一个**。当前 LSB 的伴随式告诉你要翻
转哪一个位置，而当伴随式本就吻合时，什么都不用改。

| 量 | 公式 |
|---|---|
| 嵌入效率 | `e = k / (1 - 2^-k)` |
| 嵌入率 | 每系数 `k / (2^k - 1)` 比特 |

Gate G2 在真实系数上量了两者：

| k | 效率理论值 | 实测 | 误差 | 速率理论值 | 实测 |
|---|---|---|---|---|---|
| 1 | 2.0000 | 1.9923 | 0.38% | 1.0000 | 1.0000 |
| 2 | 2.6667 | 2.6542 | 0.47% | 0.6667 | 0.6666 |
| 3 | 3.4286 | 3.4422 | 0.40% | 0.4286 | 0.4285 |
| 4 | 4.2667 | 4.2678 | 0.03% | 0.2667 | 0.2666 |

两列要一起读。提高 k 买到效率、付出容量：k=4 时每比特改动载体的频率只有 k=1 的四分
之一，但携带的载荷也只有四分之一。k 的选择就是把载荷与可检测性摆上台面直接交换。

## 2.5 收缩，以及它真正的代价

F5 是通过**递减系数的幅值**来改动它的。当幅值为 1 的系数被递减，它变成 0——而 0 不在
提取路径上，接收方会失步。F5 的对策是丢弃该块，把它的比特在下一块重发。

对这个后果的通常描述是一个直方图伪痕：正负 1 处的计数下降幅度超出嵌入本身能解释的
范围。这是对的，但低估了问题。**一次收缩事件花掉一次系数改动，却不携带任何比特。**
代价是载荷。

Gate G2 判据 C 在真实系数上以 k=3 量化了它：

| | 原版 F5 | 无收缩变体 |
|---|---|---|
| 收缩事件 | 11,742 | 0 |
| 嵌入效率 | 1.87 | 3.41 |
| 嵌入率（比特/系数） | 0.2335 | 0.4285 |

**收缩吃掉了 45.3% 的嵌入效率与 45.5% 的速率。** 原版 F5 在 k=3 时效率只有 1.87——
*比朴素 LSB 的 2.0 还差*，而后者正是矩阵编码本该超越的对象。

这才是 nsF5 的真正论据，比直方图凹陷强得多。

关于诚实的一点说明：G2 的判据 A 与 B 起初是对着原版 F5 跑的，一致地低了约 45%。那不是
实现缺陷，是这道 gate 测错了对象——因为原版 F5 **不可能**达到教科书数字。判据被移到
了算术确实成立的那段代码上，而那个缺口成了判据 C 的主题。

## 2.6 这里的无收缩变体不是 nsF5

上面用的变体是把幅值为 1 的系数递增到 2，而不是递减到 0。这保持了提取规则，并按构造
消除了收缩，足以用来量化这个代价。

真正的 nsF5 用的是**湿纸码**（wet paper codes）：嵌入方把不可用的位置标为「湿」，编码
去寻找绕开它们的解，从而保住这个简化所放弃的容量。湿纸码是 P2 的内容。

## 2.7 T4 需要从本章拿走什么

三个事实，现在都是量出来的而不是断言的：

1. replacement 留下一个成对结构不变量，matching 不留。
2. Jsteg 抹平它碰过的对，不抹平它跳过的对。
3. 去掉收缩后 F5 的效率数字分毫不差，而原版 F5 比它们低 45%。
