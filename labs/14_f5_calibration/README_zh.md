| | |
|---|---|
| 嵌入域 | jpeg-dct |
| 算法族 | f5-family |
| 检测器 | `f5_calibration` |
| 实测误报率 | 同源干净灰度 JPEG 上 0/24 |

## 校准

对 JPEG 做直方图攻击需要一份可比对的载体直方图，而你没有。校准的办法是造一个估计：解压
到像素、**裁掉 4 像素**、用**同一张**量化表重压缩。8×8 网格不再与原始块对齐，于是 DCT
分解与承载载荷的那一次几乎无关，而内容几乎没变。

量化表必须原样带过去，这不是可选项。按名义上「同样的质量」重压缩会换掉表，那就变成在比较
两个不同的量化器——产出一个关于「什么都不是」的自信数字。

## 估计量，以及它的偏差

F5 递减幅值，于是以 `beta` 为改动率：

```
h_stego(d) = h_cover(d) * (1 - beta) + h_cover(d + 1) * beta
```

在 `d` 取 {1, 2} 上做最小二乘就得到 `beta`。在干净载体上它本该读零。它读出的是
**−0.152，标准差 0.010。**

这个偏差是真的，而且有原因：载体本身已经是 JPEG 压缩过的，所以裁剪后重压缩得到的是**二次**
压缩的图像，其直方图系统性地比单次压缩的载体更向零集中。

要紧的是这个偏差是**稳定的**。0.010 的标准差对 0.152 的均值偏移，让它成为一个完全够用的
相对统计量、和一个毫无用处的绝对统计量。所以发现里报告的是「相对实测干净工作点的位移」，
从不说「改动率是 X」——而 −0.13 这个工作点是干净均值之上两个标准差，量出来的，不是挑的。

## 这个模块必须撤回的一个论断

早先的版本用 zero-excess 统计量去区分 F5 与 nsF5：收缩会把幅值为 1 的系数变成 0，nsF5 不会，
所以多出来的零应当能识别 F5。

在只有隐写图像的前提下，两者的实测区分能力：

| 载荷 | 用 zero excess 的 AUC | 用 beta 的 AUC |
|---|---|---|
| 0.05 bpp | 0.622 | 0.811 |
| 0.15 bpp | 0.736 | 0.984 |

zero-excess 这条路几乎不работает，而且不是调参不够。校准参考是**从隐写图像本身**算出来的，
于是任何改动像素的嵌入器同时也移动了参考，收缩信号在相减中没能存活。收缩在系数空间里是真实
的——gate G2 直接量了它——但校准隔离不出它。

所以发现命名的是**族**，不是族里的成员。`algorithm="f5-family"`。

## beta 靠什么区分它们，以及为什么这重要

beta 确实能区分 F5 与 nsF5，而原因直接来自 G2。收缩浪费改动，于是在同样的载荷下 F5 修改
的系数大约是两倍：

| 0.15 bpp 下的嵌入器 | 真实改动率 |
|---|---|
| F5，k=3 | 0.099 |
| 无收缩变体，k=3 | 0.044 |

这把 nsF5 的通常论据倒过来了。教科书版本是「它消除了一个直方图伪痕」。实测版本是：它付出更少
的载荷代价（G2：45.3% 的嵌入效率）**并且**在同样的消息下只改动一半的系数——这是直方图那套说法
从未提到的安全收益。

## 它教什么

校准很强大，而且不是免费的：它是**从被检对象本身**估计参考的，于是任何移动对象的东西也移动
参考。在决定一个校准统计量证明了什么之前，先问它在那次相减之后还能看见什么。
