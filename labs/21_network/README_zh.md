# Lab 21 -- 网络载体：载体自己在动

| | |
|---|---|
| 嵌入域 | network |
| 算法族 | dns-tunnel、ip-id、inter-packet-timing |
| 检测器 | `dns_tunnel`、`ip_id_entropy`、`timing_channel` |
| 实测误报率 | 种子化背景捕获上 0/12 |
| 检出 | 三条信道在各自载荷下限上均 12/12 |
| 证据上限 | DNS 与 timing 到 E4；IP ID **止于 E1** |

## 这里没有文件

之前每一种载体都是分析员握在手里的成品。而一次捕获是一扇**窗**，对着一场在它之前就开始、在它
之后还继续的对话。这个模块里每个计数都是**速率**，因为不附窗口的计数不是测量：「二十个可疑查询」
在你不知道捕获是一秒还是一小时之前毫无意义。

## 三条信道，三个合法的孪生兄弟

**DNS 隧道**把载荷放进查询标签。它的孪生兄弟是 CDN 分片与信誉查询——那些主机名又长、熵又高，而且
完全无辜。仅凭熵会把它们标出来；真正的判别式是**解析器会缓存**。真实流量大量重复——背景语料实测
唯一查询比 0.05 到 0.25——而隧道从不重复，因为每个查询携带不同的字节。流量速率、唯一性、标签长度
三者同时满足，否则不报。

**IP 标识**每包在 16 位 ID 字段里放两个字节。它的孪生兄弟是每一个操作系统：Linux 对原子数据报写零，
较老的栈递增计数，有些栈随机化。信号**不是**「这些 ID 看起来随机」——而是**同一台主机在捕获中途
改了主意**：100 个各不相同的非零 ID，夹在同源的 1,100 个零当中。

**包间时序**把载荷放进间隔里。它的孪生兄弟是抖动，而抖动幅度大且连续。信道会**量化**：背景流量
实测「前两个取值占比」为 0.027 到 0.031，有信道时高于 0.5，差了一个数量级。

## IP ID 止于 E1，而这正是结论

另外两条信道都到 E4。IP ID 没有，而理由写进了检测器本身而不是留给分析员：**一个会随机化的
TCP/IP 栈产出的证据一模一样。** 这条发现的 claim 文本里直说了这一点。要区分两者，需要「这台主机
平常怎么做」的基线——正是证据阶梯从 T0 起就在要求的同源条件，只是这次它是关于**主机**而不是相机的。

## 检测下限，明写

| 信道 | 下限 | 原因 |
|---|---|---|
| DNS 隧道 | 约 2,000 字节 | 低于 30 查询/分钟，速率检验不触发 |
| IP ID | 16 字节 | 需要 8 个被改写的包才构成一个总体 |
| timing | 12 字节 | 需要足够的间隔，前两取值占比才有意义 |

DNS 那个下限值得多说一句。在 90 秒的捕获里，1,500 字节载荷是 60 个查询——39/分钟，刚好卡在阈值下
——检出 0/6。到 2,000 字节则是 6/6。**慢速隧道能藏在繁忙流量里**，而且换任何阈值都消不掉这一点，
只会挪动这个下限。

## 载荷自身的熵会改变答案

携带压缩或加密数据的隧道产出唯一的标签与唯一的 ID，唯一性信号奏效。而携带**重复明文**的隧道产出
重复的标签：2,000 字节的单字符重复实测唯一比 **0.01**，而同样长度的随机字节是 **1.00**。唯一性
检测器什么也报不出来。

这是一个真实的漏洞，值得直说：**一个不做压缩的低水平发送方，反而意外击败了一个瞄准高水平对手的
检测器。** 建立在「隐蔽流量看起来随机」之上的检测器都继承了这个问题，而答案是一个不依赖熵的第二
信号——流量速率与标签长度仍然会响，这正是 DNS 检验要求三者同时满足而不是任取其一的原因。

## 解析器

`steganalysis.pcap` 走 libpcap 记录与 Ethernet/IPv4/TCP/UDP/DNS 头部，不向任何解码器提问。对
tshark 4.2.2 做了交叉验证：`ip.id`、`ip.proto`、`ip.flags.df`、`tcp.seq_raw` 上共 6,400 次字段比对，
外加 344 个 DNS 查询名，**零分歧**；生成的每一个 IPv4 校验和都被 tshark 判为有效。

## 它教什么

这三条里有两条完全绕过内容检查——时序信道**不改动任何一个包的任何一个字节**。击败它们的不是把包看
得更仔细，而是去看**对话的形状**：多频繁、多分散、多均匀。那是一件与本仓库其余部分不同的仪器，而且
它产出的每一个数字都必须附上窗口长度。
