# Lab 22 -- 视频：载体与自己冗余

| | |
|---|---|
| 嵌入域 | video |
| 算法族 | frame-lsb、container-append |
| 检测器 | `video_temporal_lsb`、`video_trailing_data` |
| 实测误报率 | 无噪同源片段上 0/8 |
| 检出 | 400 字节时 8/8；提取 8/8 |
| 证据上限 | E4 |

## 视频有而「一叠图像」没有的东西

静态场景的连续帧携带**相同的像素值**，所以它们的最低有效位是同一批比特。嵌入把它们随机化了。
于是「相邻帧之间的逐像素 LSB 翻转率」就区分开了「没被动过的背景」与「被写入过的背景」——而任何
单图检测器都看不到这一点，因为它需要两帧同时存在。

这是 Lab 18 的静音段换了个介质：**找到载体里本该完全可预测的那部分，然后检查它是不是。**

| | 干净 | 有载荷 |
|---|---|---|
| 帧对翻转率中位 | 0.0000 | 0.0000 |
| **帧对翻转率峰值** | **0.0054** | **0.0835** |

## 按帧对算，不是按片段算

第一版把翻转率在整个片段上取平均，在一个本该立刻发现的载体上测出 0.0076。载荷占据嵌入顺序的
前缀，所以它落在最前面的几帧，之后每一对都没被碰过；在二十三个帧对上取平均，等于把信号除以
二十三。按帧对量，同一个载荷在它实际占据的那一对上给出 0.083。

这是本仓库里第三次需要同一个修正——Lab 13 的滑窗卡方与 Lab 10 的滑窗调色板检验是同一个办法——
而且它可以推广：**只要载荷小于载体，全局统计量就会被未触碰的多数淹没。**

## 阈值是量出来的

在 16 个干净无噪片段上，帧对翻转率峰值从未超过 0.00814。工作点定 0.02，约为该上限的 2.5 倍：

| 载荷 | 峰值翻转率 | 相对干净上限 |
|---|---|---|
| 100 字节 | 0.0217 | 2.7x |
| 400 字节 | 0.0835 | 10.3x |
| 2,000 字节 | 0.3722 | 45.7x |

## 传感器噪声击败它，而检测器直说

哪怕只有轻微传感器噪声的片段，在嵌入任何东西之前，静态区翻转率就已经是 **0.487**。低位本来就
是随机的，没有什么可扰动了。

所以检测器在给出判定之前先检查**适用性**：如果片段自身的中位翻转率高于 0.05，它就以 E1 报告
「这项检查在这个载体上没有检验力」然后停下。语料里十二个片段有四个是带噪的，四个全部正确地拒绝
运行，而不是返回一个数字。

**拒绝运行也是一种结果。** 同样的动作出现在流水线拒绝把灰度校准阈值用于彩色载体、以及 Lab 21 的
IP-ID 信道因「随机化的栈无法区分」而封顶 E1。

## 头号限制，量出来了

把隐写片段用 MPEG-4 质量 3 重编码：

| | 数值 |
|---|---|
| 重编码后静态区中位翻转率 | 0.0858 |
| 检测器判定 | E1 —— 拒绝，超出噪声底 |
| **载荷是否存活** | **否** |

每一个有损编解码器都会自行改写帧间像素，这会把载荷与信号一同摧毁。**这套方法只在无损视频上有效，
别的都不行。** 一份说 H.264 文件里「未发现隐写」的报告，说的比它看起来少得多——而且按 gate G0 的
分类，任何转码流水线都是**主动看守**，无论是否有人有意为之。

## 解析器

`steganalysis.avi` 写入并遍历未压缩 AVI，不向任何解码器提问。对 ffprobe 6.x 在尺寸与帧数上交叉
验证，并与 ffmpeg 自己的解码器**逐像素**比对一致——BI_RGB 的行是自下而上存储、通道是 BGR，任一
搞错都会得到一个「看起来像视频」但镜像或颜色互换的数组。

## 它教什么

冗余是分析员持有、而嵌入方无法花掉的资产。凡是格式重复自己的地方——跨帧、跨静音段、跨调色板排序后
的邻居——那里就有一个可做的预测和一个可测的偏离。
