# Lab 05 -- ZIP 结构：格式留出的三处空间

| | |
|---|---|
| 嵌入域 | container |
| 算法族 | pseudo-encryption / archive-comment / unreferenced-gap |
| 检测器 | `zip_pseudo_encryption`、`zip_archive_comment`、`zip_unreferenced_gap`、`zip_header_disagreement` |
| 实测 FPR | 同源干净归档 0/100，每个检测器分别计数 |
| 证据上限 | 注释与缝隙 E4，伪加密 E3 |

## 共同的根因

ZIP 是倒着读的。阅读器先定位中央目录结束记录，再遍历中央目录，然后只打开中央目录
提到的东西。凡是中央目录不愿提及的，都是**按设计**不可见，不是疏忽。

因此检测器反其道而行：正向遍历本地文件头，再把两套视图与文件实际长度做对账。

## 三个变体

**(a) 伪加密。** 把通用位标志的第 0 位置起，但什么也不加密。所有图形界面解压工具
都会弹出一个它永远不会去验证的口令框，多数分析员就此绕道。数据从未被保护，只是被
贴了个标签。

检测是决定性的而非统计性的：取出存储的字节，直接尝试 inflate。如果裸 deflate 能
解开，那就没有加密——标志位说什么都不算数。

**(b) 压缩包注释。** EOCD 记录之后最多 65535 字节。结构上完全合法，默认从不显示。

**(c) 无引用缝隙。** 最后一个本地条目与中央目录之间的字节。没有任何结构指向它们，
所以没有任何阅读器会去读。本模块的嵌入器会相应地推进 EOCD 里的中央目录偏移——
一个会把压缩包弄坏的藏身处不算藏身处，测试断言了压缩包仍能打开并通过 `testzip()`。

## 复现

```bash
python3 -m pytest tests/test_labs_a.py -q
```

## 它教什么

当一种格式对自己的内容有两份描述时，就去比对这两份描述。这个模式在每一层反复出现：
这里是本地头对中央目录，Lab 04 是 `IHDR` 对 `IDAT`，Lab 06 是声明的与解码出来的
扫描长度。
