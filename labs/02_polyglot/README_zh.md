# Lab 02 -- 多态文件：两个解析器读同一个文件，都是对的

| | |
|---|---|
| 嵌入域 | container |
| 算法族 | format-polyglot |
| 检测器 | `polyglot_zip`（结构化）、`polyglot_signature_scan`（弱） |
| 实测误报率 | `polyglot_zip` 0/500；`polyglot_signature_scan` 2/500 |
| 证据上限 | 结构化 E4，仅签名命中 E1 |

## 手法

多态文件藏的是「一种解释」，不是字节。PNG 从魔数向前读，ZIP 从中央目录结束记录
向后读，两者从不争夺同一段字节，所以一个文件可以同时是两者。

本模块还会在加前缀后重新修正压缩包内部的偏移量。朴素追加的 ZIP 一样能打开，但
阅读器会打印「前面有多余字节」的警告。分析员会被训练成相信警告；一个由内行做出来
的多态文件不会产生警告。

## 为什么「它能正常显示成图片」什么也证明不了

渲染只调用了一个解析器。扩展名白名单也只是采纳了一个解析器的意见。有用的问题不是
「这是什么文件」，而是「这个问题有几个合法答案」。

## 检测

两个检测器，强弱是刻意不对等的：

- `polyglot_zip` 用真正的压缩包阅读器打开文件并逐条校验条目。结构化、决定性、E4。
- `polyglot_signature_scan` 搜索内嵌的魔数。便宜，而且错得足够频繁。

## 真正重要的实测结果

在 500 张干净合成 PNG 上，签名扫描命中了 2 次。压缩后的像素数据里包含任意字节序列，
所以 `PK\x03\x04` 会碰巧出现。0.4% 看着小，但放到百万级文件的语料上，就是四千个
需要分析员逐一手工排除的文件。

这正是 E1 存在的理由，也是为什么测试断言弱检测器**必须**误报。哪天这个数字归零，
说明干净集太小、不足以体现这个现象，而不是检测器变好了。
