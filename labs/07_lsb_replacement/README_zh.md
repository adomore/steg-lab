# Lab 07 -- LSB replacement 与 E3 天花板

| | |
|---|---|
| 嵌入域 | spatial |
| 算法族 | lsb-replacement |
| 检测器 | `rs_analysis`、`weighted_stego` |
| 实测误报率 | 来源匹配的干净载体 0/40；来源失配时 25% |
| 证据上限 | E3（仅当顺序嵌入时到 E4） |

## 这里发生了什么改变

A 组的每一个模块最后都拿到了载荷。这一个产出的是一个**数字**。

RS 分析与 Weighted Stego 估计相对载荷。它们确立了「有东西被嵌入」以及大致的量，但两者
都拿不到其中的任何一个字节——除非知道嵌入路径。所以发现止步于 E3：域已识别、存在性已
确认、载荷未到手。

这个天花板是诚实的。当嵌入是从第一个采样开始顺序进行时，载荷可以轻易恢复，发现升到
E4；当位置来自带密钥的置换时则不能，报告应当直说，而不是暗示部分提取指日可待。

## 阈值

`RS_THRESHOLD = 0.344` 与 `WS_THRESHOLD = 0.376` 不是凭口味挑的。它们是 gate G4 实测
出来的工作点：对 0.5 bpp replacement 达到 95% 真阳性的阈值，在该处两个检测器于 80 张
来源匹配的干净载体上误报为零。

## 检测性能

来自 gate G4，80 张载体上的 AUC：

| 相对载荷 | RS analysis | Weighted Stego |
|---|---|---|
| 0.05 | 0.621 | 0.594 |
| 0.10 | 0.735 | 0.840 |
| 0.25 | 0.927 | 1.000 |
| 0.50 | 1.000 | 1.000 |

Weighted Stego 同时是定量的：在全部速率上对已知载荷的平均绝对误差保持在 0.031 到
0.044 之间。

## 那个首次就失败的误报测试

零误报测试第一次运行就以 25% 失败。检测器没问题；出问题的是**基线**——它取自四种合成
图像族，其中包括局部变差近乎为零的 flat 与 gradient 图像，两个估计量在那里都会失稳。

同一个检测器、同一个阈值、不同的基线来源：

| 检测器 | 来源匹配 | 来源混合 |
|---|---|---|
| RS analysis | 0/60 | 15/60 |
| Weighted Stego | 0/60 | 15/60 |

这就是被量出来的载体来源失配。这也是 `measure_baseline` 带 `kinds` 参数的原因，以及
证据阶梯说的是**同一**来源而不是相似来源的原因。

## 复现

```bash
python3 -m pytest tests/test_labs_b.py -q
python3 gates/g4_statistical.py --n 80
```

## 它教什么

统计判定就是把一个阈值施加到一个估计值上，而没有同源基线的阈值，是一个没有附带含义的
数字。
