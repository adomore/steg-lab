# Lab 08 -- LSB matching：一个没有可用检测器的模块

| | |
|---|---|
| 嵌入域 | spatial |
| 算法族 | lsb-matching |
| 检测器 | 没有能用的 |
| 实测偏离随机水平 | 最坏 0.086，来自 gate G4 |
| 证据上限 | E0 |

## 这个模块不发布任何检测器，而这正是它的内容

LSB replacement 只能在一对值的两个成员之间移动。这个约束是一种结构，而 RS 分析、
Sample Pair Analysis 与 Weighted Stego 全都是「这个结构被侵蚀了多少」的估计量。

LSB matching 随机加一或减一。嵌入器只改了一行。那个结构根本不会形成，整个族的信号
同时归零。

## 归零得有多彻底

Gate G4，80 张载体、五档相对载荷：

| 检测器 | 0.05 | 0.10 | 0.25 | 0.50 | 1.00 |
|---|---|---|---|---|---|
| RS analysis | 0.531 | 0.532 | 0.511 | 0.518 | 0.586 |
| Weighted Stego | 0.514 | 0.516 | 0.550 | 0.532 | 0.573 |
| chi-square | 0.517 | 0.485 | 0.505 | 0.450 | 0.445 |

对比 Lab 07，那里 Weighted Stego 在 0.25 bpp 就达到 AUC 1.000。

## 为什么 `detect` 返回 E0

「因为可能存在更强的算法，所以对每张图都报 E1」，等于一个披着免责声明的、误报率 100%
的检测器。没有可以诚实报告的东西，就什么都不报。

## 试过并且没成的东西

校准 HCF 质心（Ker, 2005）是「那到底什么能检测这个」的经典答案。在本语料上实测 AUC：
0.25 bpp 时 0.482。就是随机。

那个显而易见的解释——这些载体本身的高频噪声大于 ±1 扰动——通过把载体噪声从 sigma=0.5
扫到 sigma=6.0 做了检验，结果被**证伪**：AUC 始终落在 [0.505, 0.533]。
见 `calibrated_hcf_com_UNVALIDATED` 与缺口 G-12。

## 复现

```bash
python3 -m pytest tests/test_labs_b.py -q
```

测试把这个**失败**断言为一个实测量。哪天某个结构检测器在这里开始生效，它就会变红并
要求解释——这是对的，因为最可能的原因是嵌入器坏了，而不是有了突破。

## 它教什么

从「我们有一个针对 LSB 隐写的检测器」到「我们有一个针对 LSB replacement 的检测器」，
距离是嵌入器里的一行代码。T5 的特征集与集成分类器才是这一点发生改变的地方，而知道
它们为什么必要，比被塞一个能用的检测器更有价值。
